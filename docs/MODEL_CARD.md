# Model Card: Chuvashia-RAG

Карточка составлена по шаблону *Model Cards for Model Reporting*
(Mitchell et al., Google, 2019, [arXiv:1810.03993](https://arxiv.org/abs/1810.03993)).

> **Что описывает карточка.** Мы не обучали собственную модель. Chuvashia-RAG —
> это RAG-система (retrieval-augmented generation): она находит статьи в
> векторной базе и передаёт их готовой LLM, которая формирует ответ. Карточка
> описывает систему целиком: какие модели в неё входят, на каких данных
> построена база знаний и насколько хорошо система отвечает.

## 1. Сведения о модели (Model Details)

| | |
|---|---|
| Название | Chuvashia-RAG — Telegram-бот о культуре Чувашии |
| Версия | 0.2.0 (ветка `refactor/production`); версия, оценённая на защите, — `master` от 18.06.2026 |
| Тип | RAG-система: векторный поиск + генерация ответа LLM |
| Разработчики | Cherimolah, MateLr, Rey_2903, Vsevolod Shchanov — учебный проект магистратуры |
| Дата | Разработка 29.04–18.06.2026, карточка — 30.09.2026 |
| Лицензия кода | Apache 2.0 |
| Репозиторий | https://github.com/Cherimolah/Chuvashia-RAG |

**Компоненты** (все модели вызываются через OpenRouter API):

| Роль | Модель | Где в коде |
|---|---|---|
| Генерация ответа | `deepseek/deepseek-v4-flash` | `llm.py: COMPLETION_MODEL` |
| Эмбеддинги для поиска | `qwen/qwen3-embedding-8b` (4096 измерений) | `llm.py: EMBEDDING_MODEL` |
| Классификатор «спрашивают ли о конкретном периоде» | `x-ai/grok-4.20` + outlines (структурированный вывод) | `llm.py: model` |
| Векторная база | ChromaDB, косинусное расстояние | `loader.py` |
| История диалога | PostgreSQL | `database.py` |

**Как формируется ответ**

1. Классификатор решает, спрашивает ли пользователь о событиях за период. Если
   да — поиск ограничивается статьями с датой публикации из этого периода.
2. Диалог (история + новый вопрос) нарезается на окна по 3 сообщения с
   перекрытием 1, эмбеддинги окон усредняются.
3. Из ChromaDB берутся 5 ближайших статей (`N_RESULTS=5`).
4. Статьи и вопрос передаются в LLM с системным промптом: отвечать на
   литературном чувашском языке, опираясь только на переданные фрагменты.

**Параметры генерации:** temperature 0.4, top_p 0.9, max_tokens 10000,
frequency_penalty 0.1, presence_penalty 0.1 (переопределяются через `.env`).

## 2. Назначение (Intended Use)

**Бизнес-задача.** Дать носителям и изучающим чувашский язык собеседника,
который рассказывает о культуре, событиях и истории Чувашии на литературном
чувашском языке. Для малоресурсного языка это одновременно справочник и
языковая практика.

**Основное применение**
- Вопросы о событиях, людях, праздниках и местах Чувашии, о которых писал
  chuvash.org.
- Вопросы о событиях за период («что было в Чебоксарах в мае 2015?»).
- Диалог с уточняющими вопросами (история хранится до сброса кнопкой
  «🗑 Сбросить контекст»).

**Пользователи.** Носители чувашского языка, студенты и преподаватели, люди,
интересующиеся культурой региона.

**Не предназначено для**
- Медицинских, юридических, финансовых советов.
- Актуальных новостей: база заканчивается осенью 2025 года.
- Официальных справок и цитирования без проверки по первоисточнику.
- Вопросов, не связанных с Чувашией: ответ будет собран из нерелевантных статей.

## 3. Факторы (Factors)

Факторы, от которых может зависеть качество ответа:

| Фактор | Почему важен |
|---|---|
| Язык вопроса (чувашский / русский) | Бот принимает оба, но оценка проводилась только на чувашских вопросах |
| Тематика (культура, спорт, общество…) | Покрытие тем в новостной базе неравномерно |
| Период события | Даты в базе 2005–2025; более ранние и более поздние события отсутствуют |
| Точность формулировки | Похожие события разных лет (например, ежегодные) легко перепутать |
| Длина диалога | Вся история влияет на поиск; длинный диалог «размывает» новый вопрос |

## 4. Метрики (Metrics)

Качество измерялось фреймворком [RAGAS](https://docs.ragas.io/) (LLM-as-a-judge):

| Метрика | Что показывает | Шкала |
|---|---|---|
| **Faithfulness** | Доля утверждений ответа, подтверждённых найденными статьями (защита от выдумок) | 0–1 |
| **Context Precision** | Насколько найденные статьи релевантны вопросу | 0–1 |
| **Context Recall** | Нашлась ли вся информация, нужная для эталонного ответа | 0–1 |
| **Answer Relevancy** | Отвечает ли ответ на заданный вопрос | 0–1 |

Дополнительно проводился **тест шумоустойчивости**: в найденные статьи
подмешивали 10/30/50 % нерелевантных текстов и смотрели, как меняются
faithfulness и answer relevancy.

**Порог «слабого» ответа:** любая метрика ниже 0.5.

**Судья RAGAS:** `deepseek/deepseek-v4-flash`, temperature 0 — та же модель,
что генерирует ответы (см. раздел 9).

### Разбор ошибок

5 из 20 ответов имеют хотя бы одну метрику ниже порога. Два характерных случая:

- **Поиск не нашёл статью (вопрос 13, общество).** «Сколько мешков мусора
  собрали 4 правонарушителя?» — нужной статьи нет среди 5 найденных. Бот
  честно ответил, что сведений нет, и не стал выдумывать. Для пользователя это
  правильное поведение, но все метрики RAGAS равны 0.
- **Спутаны похожие события (вопрос 12, спорт).** «Когда прошла „Лыжня
  России — 2012“?» — нашлись статьи о других лыжных соревнованиях, и бот
  уверенно назвал 16 февраля вместо 12-го. Faithfulness при этом 0.92: ответ
  верен найденным статьям, но статьи не те. Это главный риск системы — ошибка
  выглядит убедительно.

В остальных трёх случаях нужная статья найдена (Context Recall 1.0) и ответ
опирается на неё (Faithfulness 1.0), но среди найденных статей много лишних
(Context Precision 0.25–0.5).

## 8. Этические аспекты (Ethical Considerations)

- **Выдумки (галлюцинации).** В среднем около 10 % утверждений в ответе не
  подтверждены найденными статьями. Бот может уверенно сообщить неверную дату
  или имя (см. вопрос 12). Пользователь не видит источники ответа.
- **Представленность языка.** Чувашский — малоресурсный язык, в обучающих
  данных LLM и модели эмбеддингов его мало. Вероятно, качество ниже, чем для
  крупных языков, и ответы могут содержать русизмы или неточности (гипотеза,
  отдельно не измеряли).
- **Смещение источника.** Все знания — из одного новостного сайта. Вероятен
  перекос в сторону событий Чебоксар и официальной повестки; взгляды и
  события, о которых сайт не писал, бот не знает (гипотеза, не проверяли).
- **Культурная чувствительность.** Бот позиционируется как «хранитель
  традиций»: его ответы могут восприниматься как авторитетные, хотя это
  пересказ новостей, а не экспертиза.
- **Персональные данные.** Бот хранит в PostgreSQL Telegram ID, имя, username
  и всю переписку до сброса контекста. Статьи содержат имена реальных людей.
  Тексты вопросов уходят сторонним API (OpenRouter и провайдеры моделей).
- **Справедливость по группам пользователей.** Качество для вопросов на
  русском и на чувашском не сравнивалось — вопрос остаётся открытым.

## 9. Ограничения и рекомендации (Caveats and Recommendations)

**Ограничения**
- Знания ограничены статьями chuvash.org до осени 2025 года.
- Оценка на 20 вопросах — мало для надёжных выводов; вопросы только на
  чувашском и только с ответом в базе.
- Судья RAGAS — та же модель, что генерирует ответы: модель оценивает сама
  себя, метрики могут быть завышены.
- Шумоустойчивость финальной конфигурации не проверялась.
- База и её исходные данные не версионируются вместе с кодом (см. раздел 6).
- Ответ на одно сообщение — три запроса к внешним API; в тестовом прогоне
  30.09.2026 ответ занял около минуты.
- Технические ограничения кода — в [TECH_DEBT.md](TECH_DEBT.md).

**Рекомендации**
- Показывать пользователю ссылки на статьи, из которых собран ответ.
- Расширить оценочный набор: вопросы на русском, вопросы без ответа в базе,
  больше вопросов на каждую категорию.
- Использовать судью RAGAS из другого семейства моделей.
- Добавить повторное ранжирование (re-ranking) найденных статей — это
  поднимет Context Precision и снизит риск перепутать похожие события.
- Хранить исходную выгрузку и скрипт сборки базы в репозитории, а версию
  базы — вместе с отчётом оценки.
