# Технический долг

Проблемы, найденные при рефакторинге под production-стандарты (ветка
`refactor/production`, сентябрь 2026). Логику бота в рамках рефакторинга
сознательно не меняли: без токенов, PostgreSQL и собранной `chroma_db` её
нельзя проверить целиком, а риск сломать работающую систему выше пользы.
Исправлено только то, что проверяется локально (см. раздел в конце).

Приоритет: 🔴 влияет на пользователей или воспроизводимость, 🟡 качество и
стоимость, ⚪ удобство разработки.

## Уже исправлено в `refactor/production`

- Проект — устанавливаемый пакет `src/chuvashia_rag`, без `sys.path.insert`.
- Зависимости в Poetry (`pyproject.toml` + `poetry.lock`), `requirements.txt`
  генерируется из lock-файла (раньше — `pip freeze` в UTF-16 без части пакетов).
- `ragas 0.2` несовместим с `langchain-community 0.4`: без фиксации версий
  (как было в `requirements_ragas.txt`) оценка не запускалась бы на свежей установке.
- Без `LOG_LEVEL` в `.env` проект падал при импорте, хотя README обещал `INFO`
  по умолчанию.
- Отчёты оценки: `NaN` → `null`, JSON валиден.
- Сообщения без отправителя (`from_user=None`) больше не роняют хендлеры.
- ruff, mypy, pre-commit, pytest; все проверки проходят.
